# Sumo Bot

Arduino Uno firmware for sumo competition, line tracking, and standby. Startup
initializes the motors, servo, ultrasonic sensor, floor sensors, gyro, LEDs, and
IR receiver. The main loop services those devices and resets a two-second watchdog.

The sumo behavior lives in `ApplicationFunctionSet_Follow()`. It preserves the
existing opponent scan, chase/attack speeds, target memory, boundary-tape escape,
and lifted-car stop. Line tracking retains its existing thresholds and search logic.

## Controls

- The supplied IR remote's **DOWN** button starts sumo mode; other IR buttons are ignored.
- The onboard button's selection values are **1 = line tracking**, **2 = sumo**,
  and **3 = standby**. Standby stops the motors.
- To assign another remote button to a second car, change `SUMO_START_IR_BUTTON`
  in `ApplicationFunctionSet_IRrecv()` in `src/ApplicationFunctionSet_xxx0.cpp`.
  Its comment lists the decoded button values. The raw remote-code mappings remain
  in `DeviceDriverSet_IRrecv_Get()` in `src/DeviceDriverSet_xxx0.cpp`.

Serial command input, app joystick driving, obstacle avoidance, and programming
commands were removed. Serial output remains for existing startup/button messages.
The bundled IR, gyro, and I2C libraries remain dependencies of the retained behavior;
PlatformIO supplies FastLED and Servo.

## Build

```text
pio run -e uno
```

The current firmware image is `.pio/build/uno/firmware.hex`. The `.hex` already
present in `src/` is an older artifact and is not regenerated by this build.

The cleanup was checked by compiling for the Uno and comparing retained application
and driver code with the pre-cleanup source. Physical verification on the car is
still needed: check the remote start, onboard standby, opponent response, tape
escape, and line tracking after uploading.
